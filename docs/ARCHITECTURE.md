# ルール変更レター MVP

## 基本方針
立場からカテゴリを初期提案し、実際の配信対象は利用者が選択したカテゴリで決めます。

## 処理フロー
1. メール・立場・カテゴリを登録し、同意日時と方針バージョンを記録
2. 確認メールのリンクを開き、確認画面のボタンを押して購読を有効化
3. 公式情報源の候補を収集。利用条件確認前は収集停止
4. 外部IDで重複排除してD1に保存
5. キーワードでカテゴリ候補を付与
6. 記事は pending で保存し、管理者が原文を確認
7. 承認済み記事をカテゴリ照合して delivery_queue に積む
8. Cronで最大20人ずつ処理し、失敗時は最大5回再試行
9. sent に記事ごとの配信履歴を保存

## 安全方針
- 情報源の利用条件確認前は sources.terms_checked=0 とし収集停止
- 外部AI APIは使わず、未承認記事は配信しない
- 管理APIはBearerトークンを要求し、実行系はPOST
- 確認・配信停止リンクのGETでは状態を変更せず、確認画面からPOSTさせる
- プライバシー方針のHTTPS URLが設定されるまで新規登録を拒否
- 配信キューに実行ロック、試行回数、状態を保持
