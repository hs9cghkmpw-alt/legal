# 登録ハードル改善レビュー

## 変更したこと
- 最初にカテゴリ一覧を8個並べず、生活者・働く人・事業者・デジタルの4つの開始セットを提示。
- セットはボタン1回で選択でき、分野の微調整と立場による推薦は折りたたみ表示。カテゴリは必ず利用者が確認・変更できる。
- 「立場は任意」「立場そのものでは配信対象を決めない」を明記し、不要な個人属性入力への不安を下げた。
- 登録確認メール、週1回を基本とすること、該当情報がない週は送らないこと、配信停止可能、公式情報を読む必要があることを登録前に説明。
- プライバシー方針が未設定の場合、APIだけでなく画面でも登録操作を停止。方針がないのに同意チェックをさせる矛盾を避けた。

## 実装前の反証・リスク検討
- **誤った対象選択:** プリセットがユーザーの関心を決めつける可能性。対策として「開始セット」として提示し、カテゴリを展開して変更可能にした。
- **自動推薦による意図しない選択:** 立場を選ぶとカテゴリが更新されるが、利用者がカテゴリを一度でも直接変更した後は立場変更で上書きしない。
- **立場の入力が必須だと感じる問題:** 立場は任意で折りたたみ、配信対象はカテゴリ選択で決まると説明。
- **空週にメールが届かないことを不具合と思う可能性:** 登録前に明記。
- **誤認・過大な信頼:** 行政機関ではないこと、個別法律相談ではないこと、重要事項は公式原文で確認することを明記。
- **プライバシー方針未完成なのに登録させる問題:** 方針URLが空なら同意欄と送信ボタンを無効化。サーバー側の既存拒否も維持。
- **追加費用・新規外部依存:** 変更はHTML/CSS/JavaScriptとNode標準テストのみ。外部サービスやAI APIを追加しない。

## 未解決・リリース阻害要因
- 本番公開前に運営者情報・問い合わせ先・保持期間・Cloudflare/Brevoの処理・ログ/バックアップの説明を含むプライバシー方針を完成する必要がある。
- 本番公開後に実機（特にiOS Safari）でレイアウト、キーボード操作、読み上げを確認する。
- コンバージョン率は計測していないため、改善効果は仮説。個人情報を使った追跡分析は追加せず、初期は登録完了数など最小限の集計で判断する。
- この変更自体では登録を公開・有効化しない。収集元の利用条件、配信基盤、費用の検証は引き続き必要。
