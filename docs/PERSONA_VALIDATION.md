# 仮想ペルソナによるLP・登録体験レビュー

## この検証の範囲

これは実ユーザーへのインタビューやコンバージョン実験ではなく、LPの実装・登録フローをもとにした机上レビューである。したがって、離脱率や登録率を数値で断定しない。仮説は公開前のユーザーテストで検証する。

## 総合判定

**現状の方向性は良いが、信頼材料と実際の配信品質を確立するまでは公開不可。**

強みは、最初に分野セットを選べること、詳細設定を折りたためること、立場入力を任意にしていること、配信頻度・空週・停止方法を登録前に示すこと。反面、「公式情報をもとに整理する」という約束に対して、具体的な配信サンプル、運営者情報、情報の確認体制が弱い。登録画面だけではサービスの実力を評価しにくい。

## ペルソナ別の疑似ユーザーテスト

### 1. 忙しい会社員（スマホで通勤中に閲覧）
- **最初の理解:** 法律・制度の情報を自分向けに絞ってメールでもらえることは伝わる。
- **登録動機:** 労働・社会保険・税金を追いかける手間が減りそう。
- **離脱要因:** 実際にどの程度具体的な要約が届くか不明。配信イメージは形式の説明にとどまり、実際の情報例がない。
- **改善:** 実データの確認・承認フローを確立した後、出典・公布日／施行日・対象者・やること・公式リンクが分かる実例を1件掲載する。実例がまだない段階では架空の法改正を実例のように見せない。

### 2. 子育て中の生活者（法律用語が苦手）
- **最初の理解:** 「暮らしのこと」は選びやすい。
- **登録動機:** 契約、年金、交通など、生活への影響を早く知りたい。
- **離脱要因:** 「ルール変更」が広く、どんな情報が届くのか予想しづらい。「何が変わる／誰に関係／何を確認」の説明は良いが、日常の具体例がない。
- **改善:** カテゴリ名に短い具体例を添える。専門用語は本文で平易な言葉に言い換え、必要な場合は正式名称も併記する。

### 3. 個人事業主・フリーランス
- **最初の理解:** 「事業・会社のこと」は対象に見える。
- **登録動機:** 税、取引、雇用などの見落としを減らしたい。
- **離脱要因:** 「事業・会社」という表現が法人向けに感じられ、一人で仕事をする人が自分を対象だと思わない可能性がある。補助金など、サービスが実際には扱わない領域まで届くと誤認されるリスクもある。
- **改善:** セット名を「事業・フリーランス」に変える案をテストする。ただし、補助金や個別助成制度を実装していない限り、対応しているように広告しない。

### 4. 小規模法人の人事・労務担当
- **最初の理解:** 労働・社会保険・税をまとめて受け取れるのは便利そう。
- **登録動機:** 法改正の見落としを減らしたい。
- **離脱要因:** 週1回を基本とする配信では、急な期限や緊急対応を任せられない。全件検出を保証しない現行仕様と、担当者が期待する網羅性には差がある。
- **改善:** 「見落とし防止を保証」「コンプライアンスを自動化」といった表現を使わない。週次の参考情報であること、網羅性を保証しないこと、期限管理システムの代替ではないことを明記する。

### 5. 個人情報に慎重なユーザー
- **最初の理解:** メール登録サービスだとは分かる。
- **登録動機:** 自分に必要な情報だけを受け取れるなら試したい。
- **離脱要因:** 運営者・問い合わせ先、保存期間、削除後の扱い、利用する外部サービスなどを、プライバシー方針の実物で確認できない。これはUIだけで解消できない。
- **改善:** 運営者名／連絡先、収集目的、保存期間、削除方法、Cloudflare・メール配信事業者等の委託先、ログやバックアップの扱いを確定してから受付を有効化する。方針が未確定の間は登録停止を維持する。

### 6. デジタル操作に不慣れなユーザー
- **最初の理解:** 4つの選択肢から始められる点は分かりやすい。
- **登録動機:** 詳細カテゴリを読まずに開始できる。
- **離脱要因:** 「立場からおすすめ」と「分野選択」の関係が分かりづらい可能性がある。メール確認を済ませないと登録完了しない点も、送信後の案内が弱いと混乱する。
- **改善:** 立場は任意であり、選択内容を推薦するだけだと明示する。送信後画面・確認メールで「まだ登録完了ではない」「メールが届かない場合」を案内する。公開前にスマホの拡大表示とスクリーンリーダーも確認する。

### 7. 法務・税務に詳しい懐疑的ユーザー
- **最初の理解:** 行政そのものではなく、公式情報を編集する第三者サービスだと分かる。
- **登録動機:** 一次情報への導線としては価値がある。
- **離脱要因:** 「公式情報をもとに整理」の品質基準、原文との対応、更新・訂正の方針が見えない。メール見本も架空の構成例なので、要約品質を評価できない。
- **改善:** 出典URL、確認日、公布日・施行日、編集・訂正方針を記事テンプレートに含める。誤りの連絡先と訂正履歴の方針を公開する。

### 8. 登録の必要性をまだ感じていないユーザー
- **最初の理解:** サービスの仕組みは分かるが、今登録する理由は弱い。
- **登録動機:** 自分に関係する重要な変更を見逃したくない。
- **離脱要因:** 実際の配信例、対象分野の範囲、受信後にどんな行動につながるかが見えない。
- **改善:** 品質確認済みのサンプルを公開し、配信頻度・配信停止・削除を簡潔に見せる。実績や利用者数を作り上げて補わない。

## 実装・コピー検査で見つかった不具合

1. **重大：プライバシー方針URLを設定して登録フォームを有効にしても、LPの左側に「プライバシー方針が公開されるまで登録を受け付けません」と表示される。** 画面内で登録可能／不可能の説明が矛盾し、登録直前の不安や離脱を生む。条件分岐で修正し、設定済みケースをテストする。
2. **軽微：確認メールのテキスト版だけ旧名称「ルール変更レター」が残っている。** ブランドが不統一なので「ルール便」に統一する。
3. **軽微：READMEのブランド・LP節が重複している。** 文書を整理する。

## 公開前の必須条件

- [ ] プライバシー方針、運営者情報、問い合わせ窓口を確定
- [ ] e-Gov API・デジタル庁RSSの利用条件を確認し、許諾判断を記録
- [ ] 収集・抽出・承認・訂正の責任と手順を決定
- [ ] 少なくとも数件の実際の候補を原文と照合し、誤検出・見落としを評価
- [ ] 実際のメール送信、確認、停止、削除をテスト
- [ ] iOS Safari、Android、拡大表示、キーボード操作を実機確認
- [ ] 運営者以外の5〜8人にタスク形式で触ってもらい、理解・不安・離脱点を観察

## 初期テストで観察する指標

- 5秒後に「何を届けるサービスか」を自分の言葉で説明できるか
- どの情報が届くか、どの頻度か、どう停止するかを正しく理解できるか
- おすすめセットを迷わず選べるか、カテゴリ選択で迷う箇所はどこか
- プライバシーや情報の信頼性について、登録前に何を質問するか
- 登録フォーム完了率ではなく、まず「理解できない／信用できない／面倒」のどれが主な離脱理由か

**注意:** これらのペルソナ反応は検証仮説であり、実ユーザーの発言や実測結果ではない。
